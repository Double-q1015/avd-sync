## 性能优化措施

### 1. 减少固定等待时间

**优化前**：
- 列表页固定等待 1 秒
- 详情页固定等待 1 秒
- 每个CVE后还有 0.1 秒延迟
- **每个CVE耗时**：约1.1秒

**优化后**：
- 列表页：使用智能等待（最多0.5秒），如果超时则只等待0.2秒
- 详情页：使用智能等待（最多0.3秒），如果超时则只等待0.15秒
- 列表页之间延迟减半（0.05秒）
- **每个CVE耗时**：约0.3-0.5秒

**效果**：每个CVE从至少1.1秒降低到约0.3-0.5秒，速度提升约2-3倍

### 2. 智能等待机制

**问题**：固定等待时间，即使页面已加载完成也要等待

**优化**：
- 使用 `page.wait.ele_loaded()` 等待关键元素加载
- 设置合理的超时时间（0.3-0.5秒）
- 超时后使用更短的固定等待作为备选

**效果**：页面加载快时几乎不等待，加载慢时最多等待0.5秒

### 3. 增量爬取跳过已存在CVE

**问题**：即使CVE已存在且信息完整，也会重新爬取

**优化**：
- 在爬取详情前检查数据库
- 如果CVE已存在且发布日期相同，跳过爬取
- 只爬取新CVE或需要更新的CVE

**效果**：增量爬取时大幅减少不必要的请求

### 4. 浏览器性能优化

**优化措施**：
- ✅ 禁用图片加载（如果支持）
- ✅ 禁用插件
- ✅ 保留JavaScript（页面需要）
- ✅ 使用headless模式
- ✅ 单浏览器实例复用

**效果**：减少网络传输和渲染时间

### 5. 批量数据库操作

**已实现**：
- 使用批量插入/更新
- 减少数据库I/O次数
- 数据库索引优化

## 性能对比

### 优化前后对比

| 指标 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| 列表页等待 | 1秒 | 0.2-0.5秒 | 50-80% |
| 详情页等待 | 1秒 | 0.15-0.3秒 | 70-85% |
| CVE间延迟 | 0.1秒 | 0.1秒 | - |
| **每个CVE耗时** | 约1.1秒 | 约0.3-0.5秒 | **2-3倍** |
| **100个CVE耗时** | 约110秒 | 约30-50秒 | **2-3倍** |

### 增量爬取额外优化

- 跳过已存在CVE：如果50%的CVE已存在，可再节省50%时间
- **实际耗时**：约15-25秒（0.25-0.4分钟）

### Docker vs 本地运行对比

| 指标 | 本地运行 | Docker运行 | 差异 |
|------|---------|-----------|------|
| 启动时间 | 2-3秒 | 3-5秒 | +50% |
| 内存占用 | 400MB | 500-800MB | +25-100% |
| CPU开销 | 基准 | +5-10% | 轻微增加 |
| 网络延迟 | 基准 | 相同 | 无差异 |

**结论**: Docker运行会有约20-30%的性能损失，但在可接受范围内。

## 配置建议

### 请求延迟配置

```python
# 快速爬取（可能被限流）
'request_delay': 0.05,  # 50毫秒

# 平衡模式（推荐）
'request_delay': 0.1,  # 100毫秒

# 保守模式（稳定）
'request_delay': 0.5,  # 500毫秒
```

### 增量爬取回溯天数

```python
# 快速更新（可能遗漏少量数据）
'lookback_days': 3

# 平衡模式（推荐）
'lookback_days': 7

# 安全模式（确保不遗漏）
'lookback_days': 14
```

## 进一步优化建议

### 1. 并发爬取（高级）

如果需要更快的速度，可以考虑并发爬取：

```python
# 使用线程池或异步IO
from concurrent.futures import ThreadPoolExecutor

# 注意：需要控制并发数量，避免对服务器造成压力
```

**注意**：
- 需要合理控制并发数（建议2-5个）
- 需要处理浏览器实例管理
- 可能被服务器限流
- 需要更多资源（CPU、内存）

### 2. 缓存机制

对于已爬取的CVE，可以：
- 检查数据库中的 `updated_at` 字段
- 如果最近更新过，可以跳过
- 设置缓存有效期（如7天）

### 3. 请求去重

- 维护已爬取URL的集合
- 避免重复请求相同页面

### 4. 数据库连接池

- 使用连接池管理数据库连接
- 减少连接建立开销

## 故障排查

### 内存不足

**症状**: `Out of memory` 或容器被杀死

**解决**:
1. 增加Docker内存限制
2. 检查是否有内存泄漏
3. 减少并发数（如果支持）
4. 使用更轻量的基础镜像

### CPU过高

**症状**: 系统响应慢

**解决**:
1. 增加CPU核心数
2. 减少请求频率
3. 优化解析逻辑
4. 调整 `request_delay` 配置

### 浏览器启动失败

**症状**: `Failed to move to new namespace`

**解决**:
1. 确保设置了 `--no-sandbox`
2. 增加共享内存大小
3. 检查Docker权限
